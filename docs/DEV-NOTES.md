# Dev notes (durable constraints; no diary)

## Economy and growth
- Glow (`pets/glow.js`): 1 per question answered, +1 right, +2 whole set, 6 per growth stage, 10 for today's three, fire = min(5, run of days) on a day that earned. Time never pays; answers under 1000 ms and skips pay 0; each question pays once per local day. Levels: 0,15,36,63,99,144,198,264,342,435 then +108.
- 0-3 stars survive only as run feedback and mood weight (0.4+0.2*stars). New rewards/achievements/decor read `derivePets().glow/.sources`, never stars.
- Stages: `stageOf(done,total)`; stage 1 = first right answer, 10 = every question of the subject. Ages (`pets.js AGES/ageOf`): Baby 0-2, Growing up 3-6, Grown up 7-10. New growth visuals key off `ageOf(stage)`, never a new counter. A new village is all babies; Settings has Start over (asked twice; clears stores + local/sessionStorage).
- Items inside a level are dealt per learner (`core/learning/order.js byLearner`, seed `catos:order-seed`; Node uses a fixed seed). Never hard-code a fixed first item.
- Growth cards/parties show only after a run (`checkParties(true)`); any other arrival stores `catos:stages` silently, else a restored backup pops a focus-trapping modal.
- Houses order in `HOUSES` is deliberate (as CAT weights sections); do not reorder it to match a request's list.

## Village and UI
- Friend card order: hero, name, "Teaches X", mood, the single Help CTA, level bar, "More ways to practice", Achievements button (lore lives in a native `popover`). Presentation tweaks must not touch `economy.js` math.
- Never name a CSS class `.now` (world.css `.now` is a fixed bottom bar) or `.cw-glow` (lamp halo; the Glow icon is `cw-orb`). Use `is-now`/`is-on`.
- `.run` screens scroll `.run__body`, not `window`; `window.scrollTo` is a no-op inside them. Wide (>=64rem) RC splits passage|question, `<details class="reread">` forced open.
- Colour: only `world.css` declares `--g-*`; a token declared in two sheets breaks one theme. `justify-content:center` on an overflowing scroll container makes the top unreachable. `translate` animations fight `translate` positioning: position with `transform`. `.x{display:grid}` beats `[hidden]`. A CSS custom-property `url()` resolves against the stylesheet, not the element.
- Living painting: a patch is the painting's own pixels (identical at rest); a moving cut must extend past its edge by more than it moves or the static copy ghosts; baked feathered alpha, not CSS masks (36 masks halved frame rate on Intel HD 520); halos use plain alpha, not blend modes. Measure with 600-frame rAF windows.
- Every running CSS animation is restyled on every frame the page draws (composited or not), so the loop's rAF makes them cost: pause what is off screen (`[data-off]`), animate lamp halos only after dusk, and never add per-house CSS animations; draw moving house things on the scene canvas. Headless Chrome is GPU-bound (SwiftShader): compare cost per frame (trace FireAnimationFrame + UpdateLayoutTree per rAF), not fps. Block the service worker while measuring.
- The grown painting (`houses.js bakeVillage`) replaces what `.cw-art` shows; anything cut from the painting (motion atlas, water) must take its pixels from the graded copy or it shows as a brighter patch. HTML subject plates sit over the painting: keep house features clear of `SIGNS` boxes.
- Pet off screen: life.js skips its style writes (a phone sees a third of the map). Text on the canvas goes through `glyphSprite` (per-frame fillText was the top hot spot).
- Dialogs go through `ui/modal.js` (pass `returnTo`; iOS taps do not focus buttons). The village onboarding awaits taps inside `render()`, so "render returned" is not "screen ready".
- A friend's panTo started inside a tap's pointerdown is cancelled by the viewport's handler; defer 30 ms.
- Walking: a friend STANDS only on a node and TURNS only at one (`life.js walkTo` routes from `a.node`, the node it is at or heading for). Never add an x/y offset to a walk: a ±16 px "chore jitter" put Biscuit on the cottage railing, and ±30 px chats stood off the paving (the painting is one flat image, so 5 px off the road already reads as standing on a fence). Two friends side by side use neighbouring nodes (`CHATS`, `HOMES[].side`). Who holds a node is asked of the friends (`taken`), never kept in a set: a set that forgot to release left every spot taken within minutes and the village stopped roaming. `tools/check-walk.mjs` replaces the page's rAF with its own (~190 frames/s, 20 ms each) and fails on any friend more than 1 px off an edge; the edge walk over the painting is sampled in `check-village-data.mjs`. A new walk starts from `a.node`, and a friend within 0.5 px of the first node is "on" it: dropping the node when a friend is a few px short of it cuts the corner off the path.
- Roaming is tuned so about a third of friend-time is spent walking (10 simulated minutes, all eight friends; a visit every minute or two). A trip is ~25 s of path there and back, so only a few decisions in a hundred are a stroll (`decide`: chores below 0.7, or 0.6 when out; social call 0.85 to 0.96; strolls from 0.96) and `nextSocialAt` spaces calls 15 to 35 s. Raise those for a calmer village, lower them for a livelier one; re-measure, because walking share moves fast with them.
- Visits (`pets/visits.js`): a beat is `[who, text, chore?]` or `'go'`. The scene lives in `life.js` (`visit`): both friends are in state `wait` with `partner` set, so nothing else picks for them; a chore beat borrows `startChore(a, kind, ms)` and a friend with a partner returns to `wait` when it ends. A party, an introduction or a three-minute timeout ends it (`endVisit`). Add a scene by adding data: `check-pets` insists on turns, real chores, the copy rules and both ways for every best friendship. One social call at a time (`nextSocialAt`): more would put half the village on the road.
- Chai's library geometry in `library.js` and `library.css` must agree: PAD 92, CROWN 76, HEAD 20, BOOKS 134, PLANK 19, FLOOR 128, five 173 px rows, 1069 px case. The taller bindings keep a 44 px minimum touch width. The floor ledger is anchored below the books, never fixed over them; phones scroll vertically, shelves swipe horizontally, navigation stays fixed with safe-area offsets. Number and title labels have opaque backgrounds above dust, and locked numbers hide visually while accessible names remain. `--bk-cover` owns the rendered material colour (including vellum and gold), separately from the inline shelf palette `--c`; the opening cover copies that resolved colour. Never add an edge fade over text (a past one failed contrast). Shelf plates are sticky in the horizontal scroller. The camera temporarily disables smooth scrolling, stops on touch/wheel/key, and stories run after render returns. `catos:shelf` only diffs the last look; more than three changes suppress the restoration story. The room disables the generic place-in animation: its retained transform otherwise makes fixed navigation scroll away. The doorway fade handles entry. Motion respects both the app setting and system preference; offscreen decorative loops pause via IntersectionObserver, and timers/listeners clean up when leaving. `assets/art/library-walnut.jpg` is the generated 768 px material texture (built-in ImageGen; prompt: seamless flat aged warm walnut, vertical grain, satin wax, even light, no objects, text or perspective). Art JPG/WebP files are now included by `build-precache.mjs`. `tools/check-library.mjs` covers real taps, idle poses, progression thresholds, restored shelves, narrow layouts and reduced motion; set `CATOS_LIBRARY_SHOTS` to save previews. Direct session tests must still use an unlocked Foundation book (rc-0040).
- Voices: `SIGNATURE` (pets.js) per friend, played by `world/audio.js signature()`: a tone-built call per friend (`CALLS`: Chai's owl hoot, Toffee's crackle, etc.); only Mochi still speaks its name (Web Speech, blip fallback). No other friend uses a speech engine. Friend lines: 96 chars max (arrive/arriveNight 32, cheer 30: they sit in a 2 second bubble), no em dashes, none of the mentor's banned words, every line unique, and a floor per kind so a daily visitor keeps hearing new ones (`check-pets`). Idle and arrival bubbles are dealt by `dealLine` as a shuffled deck kept on the device (`catos:heard`), so a line does not return until the friend has said them all; add lines freely, never reorder to "fix" a repeat.

## The game
- A word in a duel is one `LexRound` answer, so `feed.next()` must follow every `feed.answer()`, and a duel's `moves` may never ask a feed for more than its `total`. Words the duel never reached are simply not asked and not recorded.
- Decode answers are the only answers kept on a `duel` record, and that is what stops a duel paying Glow twice.
- Every rule of attention in `docs/PRODUCT.md` §Why it holds attention must stay honest: the teaser is a promise (`drawCards` puts it first), a near miss is only claimed when true, and nothing pays for time.
- Players use the Web Animations API for coupling and joining; it respects `reduced()`.
- Sound, one voice at a time. `world/audio.js wake()` runs on every tap and restarts the village song if it is not playing, so anything with its own sound must call `holdMusic(true)` (a plain `stopMusic()` lasts until the next tap: that was the overlap the owner heard in 3.18.0). `play()` is a small mixer: sounds named in `BIG` wait for the big sound before them and duck the music, small sounds landing inside one are played at 40%, and the same sound asked for twice within 70 ms plays once. At a call site, order sounds with `delay` rather than stacking them (the rope answers a paragraph's own tap 0.1 s later; the winning pull is `finish()`'s alone).
- Any Muddle can be fought at any stop, so `check-duel.mjs` simulates every bout at stop 1 and stop 9. A duel's clock (`DUEL.MAX_SECONDS`) counts rope time only; counting wall time ended a duel the moment a slow reader came back from a paragraph.
- A passage in a duel cannot be half saved: `screen.js` holds the rope three short of either end until the last question, then lets it go. Leaving mid-passage is a forfeit and saves no reading.
- Adding a Muddle: a `BOUTS` row, a `CAST` row and an `EXTRAS` painter in `tools/paint-muddles.mjs` (`node tools/paint-muddles.mjs <id>` paints one and rewrites `muddle-sheets.js`), and its lines in `content/duel/muddles.json` (an optional `skim` list is said when a passage is "read" impossibly fast).
- The Muddles' sprite sheets are WebP (a tenth of the PNG size, with alpha). `cdp-lite` serves `.webp` so a gate sees what a phone sees.

## Learning core
- `noticing.js` returns nothing when nothing true can be said; do not force it to speak.
- Drafts (all six engines): `restore()` re-marks every choice against the item, declines unless `sameSet`, stores `elapsed_ms` not `started_at`, clear the draft only after the record is saved. A passage id is `meta.id`, use `passageId(p)`.
- Skill ledger revisit days `[3,3,7,14,30]`; `dueSkills()` sits between weak and new in `nextSkill()`.
- Mentor voice lint bans "wrong/weak/mistake/failure/bad/poor/careless" in `voice.js` strings.

## Content
- Pipeline: write files → `check-content` → `build-index` + `build-manifest` → `qc-corpus` / `option-tells` → `verify`. Authoring contract: `content/taxonomy/AUTHORING.md`.
- `content/CATALOGUE.md` is the corpus gist (one line per item, written by `build-index`): read or grep it to learn what exists before writing; keep every new `meta.theme` under 200 characters so the gist line carries the whole idea.
- RC v5: `word_count` counted (+-10%); `estimated_time_min` = reading_time + sum(q)/60 (+-25%); question `patterns` subset of `meta.reasoning_patterns`; explanations never name option letters. `batch_id` must match `batch-rc-NNN`; `meta.skills` uses hyphenated skill names. RC size rule `journey.js STAGE_SIZE`: at most 4 questions, 650 words; Foundation 3 paragraphs / 3 questions / 350 words. Every passage has `mentor.eli10`.
- Sourcing: no Aeon, The Conversation, CAT papers or coaching mocks (copyright). Use originals in CAT register or public domain (author died before ~1956, published before 1931). FITB/grammar are not in CAT.
- Content agents cost ~400k tokens per 6 passages; max 2 agents at a time (4-core machine).
- Placement/completion/arguments run dry fast (SP 62, PC 46, CR 6); `confusable` and `decode` word-bank shelves are empty.
- Batch recipe that worked (October 2026, rc-007 / pc-004 / sp-003): strong model drafts in a compact author format from a brief that names genre, stage, move, voice and seed per item; Sonnet assembles the JSON and mentor blocks and runs `check-content`; then `option-tells` (the key was the longest option in 37% of fresh questions before repair), `rc-style-audit` (tic phrases), a Sonnet blind solve with and without the text (`blind-solve.mjs strip … --no-text`), and `rc-quality-report` rows. ## Shipping
- `build-precache.mjs` after any precached change and after every `APP_VERSION` bump (`app.js`). New `src/pets/*.js` files too. `service-worker.js`, `content/index.json`, many src files are CRLF.
- Bump `APP_VERSION`, add a CHANGELOG entry at the top of `docs/history/CHANGELOG.md`, commit, push `origin/main`.
- Android release: bump `versionCode` (must rise every upload; scheme `MAJOR*10000+MINOR*100+PATCH`, 3.11.0 = 31100) and `versionName` in `android/app/build.gradle`, then from `android/` on the Mac: `ANDROID_HOME=~/Library/Android/sdk JAVA_HOME=~/Library/Java/JavaVirtualMachines/jdk-17.0.20.1+1/Contents/Home ./gradlew bundleRelease` → `app/build/outputs/bundle/release/app-release.aab`, upload in Play Console. Toolchain: JDK 17, SDK 36, the wrapper's Gradle. The upload key is `CAT OS/android-keys/catos-upload.jks` (password in the README beside it), read through git-ignored `android/keystore.properties`; never commit either. `android/app/google-services.json` (Firebase console, project `cat-os-612e8`, Project settings, the Android app) is git-ignored too and the build fails without it. Google sign-in works only for keys whose SHA-1 is in that Firebase app: Play's app signing key, the upload key and the debug key are there. Debug builds use Google's test ad unit.
- The app's web files are copied at build time: a web change ships to Android only with a new AAB. Building while `verify.mjs` runs starves its browser sections (check-walk failed that way once); run them apart.
- Pro products in Play Console (Monetize, Products): `catos_pro_monthly` ₹199 (sub, base plan `monthly`), `catos_pro_yearly` ₹999 (sub, base plan `yearly`), `catos_pro_lifetime` ₹2,999 (one-time). Prices live only there; the page shows what Play returns. A new product id must exist and be active before the AAB that asks for it reaches testers, or its plan reads "Not available yet".
- The opening video (`shell/intro.js`) is the vertical 1080x1920 file only, letterboxed with `object-fit: contain` because its logo runs edge to edge. Its audio is the file's own (it follows the Music setting). It lives in `assets/intro/`, which `build-precache.mjs` does not list, so the web never downloads it; the APK carries it through `copyWeb`. A failed or stalled video ends the intro (4 s to start, 9 s at most) and the curtain has a 15 s failsafe in `index.html`.
- A WebView cannot download blobs or use Web Share: `backup.js` and `shareApp()` go through the bridge (`saveFile`, `share`). Anything new that needs the OS goes there too.

## Browser verification (no npm, no Playwright)
- `cdp-lite` launches Chrome with `--mute-audio`: a gate plays whole duels and must never be heard (owner, 2026-11-10).
- `tools/cdp-lite.mjs`: `findChrome`, `serveRepo` (async), `launchChrome`, `open`, `shot`, `send`, `close`. Bypasses the service worker and reloads with ignoreCache on purpose, so offline tests need that turned off for that leg. `open()` = navigate + reload and eats one-shot UI; arrive by `location.hash` for return-toast checks.
- Git Bash mangles `#/route` argv: prefix with `MSYS_NO_PATHCONV=1` or hardcode the hash. Never put JS template literals in bash heredocs or `node -e`; write scripts with Write.
- "A tap does nothing": reproduce with a real CDP mouse event (`Input.dispatchMouseEvent` pressed + released) and `document.elementFromPoint` at the control's centre. `el.click()` skips hit testing, so a control under `pointer-events: none` or under another layer still "works" in a gate (3.8.2's word-round Begin hid behind it for a month).
- Wait for the screen, not a clock: `window.__catosBooted && #view.children.length && !.route-waiting`. `Runtime.consoleAPICalled` is an event; capture console by patching `console.error` in page.
- `SEED` (exported by `check-rendered-contrast.mjs`) is the one "learner a week in" fixture. Seed via `import('/src/core/storage/indexeddb-adapter.js')` in page context; settings `{id:'valley'}` skip the intro.
- Chrome is at `C:/Program Files/Google/Chrome/Application/chrome.exe`; never `taskkill /IM chrome.exe` (kills the owner's Chrome); a stale server may own `:8765`; Python is not installed.
- Full verify takes more than 10 minutes: `run_in_background`. Never run two Chromes while measuring.
- Headless Chrome only answers `Page.captureScreenshot` on the village if the page is "in front": `Page.bringToFront` and `Emulation.setFocusEmulationEnabled`, and use JPEG (a 3000 px PNG clip times out). To watch minutes of village life in seconds, replace the page's `requestAnimationFrame` before it loads (`Page.addScriptToEvaluateOnNewDocument`) and call the queued callbacks yourself with a clock that moves 20 ms a call (a bigger step trips the loop's "slow device" 30 fps mode): `tools/check-walk.mjs`.
- RC DOM: `#begin` → `#to-questions` → click option's inner `button` → `#submit` → `#next` → `.result`. Select an option via `cat-option-select` CustomEvent on `cat-question-card`.

- A real Android WebView can be driven the same way: debug builds enable WebView debugging, so `adb forward tcp:9333 localabstract:webview_devtools_remote_<pid>` exposes the page (pick the target whose URL contains `appassets`; AdMob runs a hidden WebView too). Notifications are inexact alarms: to fire one on an emulator, `adb root` and set the clock at least 70 minutes past its time.
